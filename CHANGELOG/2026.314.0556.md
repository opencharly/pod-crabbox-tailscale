## Why there is no ABSENCE / PERFORM step — and what the discriminator is

This is the one design point a reviewer should not read as an omission. Every other `pod-crabbox*` bed has the three-step shape because its subject starts **late**: the lease unit consumes the inputs and only then does the engine or cluster come up, so an ABSENCE step has something to be absent about. *This* image's subject starts at the **entrypoint** — there is no bootstrap gate between container start and the daemon — so by the time any live step runs, `tailscaled` is already up. Manufacturing a step 1 would mean adding a gate to the product for the test's benefit, which R3 forbids.

**The discriminator is structural, and it is pinned by a sibling check.** Before `#3` the image shipped neither `/usr/local/libexec/crabbox/tailscaled-start` nor an entrypoint that starts it, so the daemon could not run at all; `tailscale-entrypoint` asserts both exist and are wired, and this bed asserts the consequence at runtime.

**A mutation run against the base image is not expressible, and that is pasted rather than asserted.** Pointing the bed's `image:` at `pod-crabbox` was tried:

```console
$ charly check run check-pod-crabbox-tailscale-contract      # bed had image: pod-crabbox
charly check run check-pod-crabbox-tailscale-contract: [image-build] FAIL after 50.585s: exit 1: charly subcommand exited 1
charly check run check-pod-crabbox-tailscale-contract: FAIL (steps=1)

$ tail -2 .check/check-pod-crabbox-tailscale-contract/2026.314.0502/image-build.log
charly: error: command "build": scoping generation to requested boxes: unknown box "pod-crabbox"
charly subcommand exited 1
```

`image:` resolves to a **box of the bed's own project**, so a bed cannot deploy another repo's box and the cross-image control is unreachable. That is filed as **`opencharly/plugin-check#143`** (see Filed issues) rather than left as a sentence here.

**The tailnet join is deliberately not asserted.** `tailscale up` needs an auth key that a lease venue does not carry; R8 says a live boundary runs live or **skips visibly**, never mocked. What the image owns — the daemon running, with the workaround, on its socket — is what this bed proves.

**Round-1 RCA, the missed control.** My pre-push gate ran the bed and it **passed**, and I read the green as proof of the daemon. It only proved that *something* matching the pattern carried the variable — and that something was the observer. A detector must (a) identify its subject by kernel identity, never a substring that its own invocation contains, and (b) be shown able to fail. Both are now enforced on every run by `tailscale-detector-can-fail`.
